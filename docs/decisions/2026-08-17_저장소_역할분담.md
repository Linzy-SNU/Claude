# 저장소 역할 분담 — iCloud는 저장소, Notion은 검색·공유

**날짜**: 2026-08-17

## 배경

사용자가 iCloud · Google Drive · OneDrive · Dropbox를 모두 쓰고 있고, Notion과
Slack도 연동돼 있다. "인프라를 최대한 활용하고 싶다"는 요청이 있었다.

문제는 **어디에 무엇을 둘지 규칙이 없다**는 것이었다.

## 리서치

| 자료 | 반영한 내용 |
|---|---|
| [PARA / Building a Second Brain](https://www.buildingasecondbrain.com/) | 도구가 아니라 **역할**로 나눈다 |
| [클라우드 계정 통합 가이드](https://fast.io/resources/consolidate-multiple-cloud-storage-accounts/) | 사용자 절반 이상이 3개 이상 클라우드를 쓰며, 중복·버전 혼란이 생긴다. 해법은 **단일 진실 원천(SSOT)** |
| [Zotero + Obsidian 학술 워크플로](https://medium.com/below-the-abstract/academic-research-workflow-zotero-obsidian-b57f687cb8ff) | 라이브러리와 노트의 역할을 분리하는 구조 |

## 결정

저장소마다 **역할을 하나씩만** 준다.

| 저장소 | 역할 |
|---|---|
| GitHub `Linzy-SNU/Claude` | **진실의 원천** — 텍스트·기록·스킬·결정 로그 |
| iCloud `05.Claude_Output/` | **저장소** — 완성 문서 원본(.docx/.pdf) |
| Notion | **문서 검색·공유용** — 요약과 위치 등록 |
| Google Drive | 학교 제출·공유가 필요할 때만 |
| Dropbox / OneDrive | **손대지 않는다** (기존 개인 파일 보관 중) |

사용자가 직접 정리한 표현: **"아이클라우드 - 저장소 / 노션 - 문서 검색 공유용"**

## 이유

- 같은 파일을 여러 클라우드에 두면 어느 게 최신인지 알 수 없다 (리서치 2)
- Dropbox·OneDrive에는 이미 개인 파일이 있어 섞으면 안 된다
- GitHub만 계정·기기가 바뀌어도 `git pull`로 완전 복원된다
