# 메모리·노트 도구 검토 — 옵시디언 배제, basic-memory 보류

**날짜**: 2026-08-18
**결론**: 새 도구를 넣지 않고, 파일 + 훅으로 해결. `basic-memory`는 조건부 후보로 남김.

## 배경

사용자 요구: *"계정이나 AI agent가 다르더라도 하던 작업이 안 끊기고 이전 내용을 알 수 있게"*
+ *"검증된 것만 하자"* + *"뭐가 최선인지 찾아보고"*

## 후보 비교

| 방법 | 컨텍스트 비용 | 확실성 | 판정 |
|---|---|---|---|
| **SessionStart 훅 주입** | 파일 크기만 | **기계적 보장** | ✅ 채택 |
| AGENTS.md에 "읽어라" 규칙 | 파일 크기만 | AI 준수에 의존 | 보조 |
| 호스팅형 MCP 메모리 서버 | 스키마만 20~40만 토큰 | 보통 | ❌ 배제 |
| 옵시디언 | 0 (AI와 무관) | — | ❌ 배제 |
| `basic-memory` (파일 기반 MCP) | 도구 20개+ | 보통 | ⏸ 보류 |

## 채택: SessionStart 훅 주입

[Claude Code 훅 공식 문서](https://code.claude.com/docs/en/hooks) 확인:

> "Claude Code adds plain-text stdout as context that Claude can see and act on"

`SessionStart`의 stdout이 **컨텍스트에 그대로 주입**된다. matcher는 `startup` /
`resume` / `clear` / `compact` — **컨텍스트 압축 시에도 다시 주입**할 수 있다.

**왜 규칙보다 나은가**: "AGENTS.md에 읽으라고 써두기"는 AI가 지시를 따라야만
작동한다. 실제로 이 세션에서 Claude가 등록된 규칙을 두 번 어겼다(근거 없는 단정,
유튜브 검색 누락). 훅 주입은 판단을 거치지 않는다.

**검증**: 새 세션에 "자동 주입된 상태가 있나"를 물어 `현재작업.md`의 내용을
파일 접근 없이 그대로 답하는 것을 확인했다.

근거 문헌:
- [Anthropic — 컨텍스트 엔지니어링](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): 장기 작업의 해법은 **구조화된 메모**
- [Cline Memory Bank](https://cline.bot/blog/memory-bank-how-to-make-cline-an-ai-agent-that-never-forgets): 갱신은 **선택이 아니라 절차**여야 한다

## 배제: 옵시디언

볼트는 **그냥 마크다운 폴더**다 ([비교 자료](https://www.atlasworkspace.ai/blog/obsidian-vs-logseq)).
따라서 설치해도 AI가 읽는 내용은 동일하고, **"계정·AI가 바뀌어도"에 기여가 0**이다.
사람이 노트를 탐색하는 도구이지 맥락 유지 수단이 아니다.

→ 나중에 사용자가 직접 탐색하고 싶어지면 기존 저장소를 볼트로 열면 된다.
   지금 안 해서 잃는 것 없음. 단, `obsidian-git` 플러그인은 **켜지 말 것** —
   기존 git 훅과 동시에 커밋해 충돌한다.

## 배제: 호스팅형 MCP 메모리 서버

[비교 자료](https://mnemoverse.com/docs/library/memory-mcp-servers-compared) 기준.

장점은 실재한다 — 의미 기반 검색(표현이 달라도 찾음), 자동 기억 추출,
도구 간 공유, 규모 확장.

그러나: Mem0 $19/월 · Supermemory $19/월 · Mnemoverse $29/월,
데이터가 남의 서버에, **백엔드 간 표준 내보내기 형식이 없어 이식 불가**.
→ "git pull하면 다 알 수 있게" 원칙과 정면 충돌.

## 보류: basic-memory

같은 MCP지만 성격이 다르다. [저장소](https://github.com/basicmachines-co/basic-memory) 확인.

**확인된 사실 (2026-08-18)**

| 항목 | 결과 |
|---|---|
| 비용 | 무료 (`uv tool install`). 클라우드는 선택, $15/월 |
| 라이선스 | AGPL-3.0 오픈소스 |
| 저장 형식 | **평문 마크다운** — "Plain text on your disk. Forever." |
| 오프라인 | 완전 동작. 계정 불필요 |
| 규모 | 3.7k 스타, 커밋 1,712개 |
| 설정 | `BASIC_MEMORY_CONFIG_DIR`로 config·DB 위치 지정 가능 ([공식](https://docs.basicmemory.com/reference/configuration)) |

호스팅형의 비용·종속·이식 문제를 대부분 비껴간다.

**아직 확인 못 한 것 — 도입 전 반드시 확인**

- [ ] **저장 경로를 저장소 안(`/Users/linzy/Claude/`)으로 지정 가능한가?**
      2차 출처는 `BASIC_MEMORY_HOME` / `BASIC_MEMORY_PROJECT_ROOT`를 언급하지만
      **공식 configuration 문서에는 `BASIC_MEMORY_CONFIG_DIR`만 있다.** 출처가 어긋난다.
      못 하면 기억이 저장소 밖에 남아 "git pull" 원칙이 깨진다
- [ ] **MCP 도구 20개+의 실제 토큰 소비량.** 매 세션 스키마로 컨텍스트를 먹는다
- [ ] SQLite 인덱스가 프로젝트 폴더에 들어가는지 (들어가면 `.gitignore` 필요)

**보류 이유**: 무료라 잃을 게 적지만, 오늘 만든 훅 주입 방식이 실제로 잘 도는지
며칠 써봐야 한다. 지금 함께 넣으면 문제가 생겼을 때 원인을 가려내기 어렵다.

**재검토 시점**: 노트가 수백 건이 되어 키워드 검색이 한계에 부딪힐 때,
또는 훅 주입 방식이 안정적으로 도는 것이 확인된 뒤.
