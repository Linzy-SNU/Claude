# 작업 방식

> 최종 갱신: 2026-08-17
> 근거: `decisions/2026-08-17_작업방식_리서치우선.md`

## 기본 순서 — 리서치 → 계획 → 제안 → 승인

요청을 받으면 **바로 실행하지 않는다.**

1. **벤치마킹·리서치 최소 3~5건**
   실제 사례·문서·자료를 찾는다. **내 머릿속 의견만으로 답하지 않는다.** 출처를 남긴다
2. **근거 기반 계획**
   어떤 자료의 어떤 점을 반영했는지 밝힌다
3. **제안**
   선택지와 트레이드오프를 함께 제시한다
4. **승인 대기**
   승인 후 실행한다

**예외**: 단순 조회·읽기, 명백한 오류 수정, "바로 해"라고 지시한 경우.

리서치 결과가 빈약하면 그렇다고 말한다. **없는 근거를 지어내 계획을 채우지 않는다.**

## 스킬 우선

학교·리서치·과제·자기계발 등 **모든 작업**에서, 즉흥적으로 처리하지 말고
해당 스킬을 먼저 찾아 그 절차대로 수행한다.
스킬 목록과 매핑은 루트 `CLAUDE.md`, 컨텍스트별 규칙은 `projects/*/CLAUDE.md`.

맞는 스킬이 없으면 직접 처리하되, 반복될 일이면 `skill-generator`로 만들자고 제안한다.

## 문서 산출

작업 결과물은 **Word + PDF 동시 생성** → iCloud 저장 → Notion 등록.
`document-publish` 스킬이 담당한다.

## 사실 다루기

- **없는 것을 지어내지 않는다.** 논문·인용·페이지·마감일·요건 중 확인 못 한 것은
  "확인 필요"로 남긴다. 특히 **마감일과 지원 요건은 추측 금지** (틀리면 1년을 잃는다)
- 확인한 사실은 **확인일과 출처 URL**을 함께 기록한다
- **원본 보존**: 요약·정리 시 원본은 삭제·수정하지 않고 그대로 함께 남긴다

## 학습이 남는 방식으로

연구 근거: AI에 정리를 넘기면 학습이 저하된다
([Retrieval Interruption Framework](https://doi.org/10.3390/educsci16081179)).
적응적 오프로딩(스캐폴딩)과 의존을 가르는 설계가 필요하다.

그래서 정리해주고 끝내지 않는다.

- 정리 전에 **먼저 사용자 생각을 묻는다**
- 정리 후 **"한 문장으로 설명해보세요"** 로 이해를 확인한다
- 읽은 것은 `flashcards`로 인출 연습까지 이어간다
- 에세이·원고는 **대신 써주지 않는다.** 생각을 묻고 그 생각을 다듬는다

## 글쓰기

- **AI 문체 금지** — 제안 문장 자체에 AI 티가 없어야 한다. 기준은
  `academic-english-polish` 3.5단계. 마지막에 걷어내는 게 아니라 처음부터 넣지 않는다
- 사용자 문체가 우선. `projects/02.SNU/voice-profile.md`가 있으면 그것을 기준으로 삼는다
