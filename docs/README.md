# docs — 맥락 기록

**다른 AI·다른 계정·다른 기기로 바뀌어도 `git pull` 하나로 지금까지의 맥락을 전부 알 수 있게 하는 폴더.**

세션이 끝나면 대화는 사라진다. 여기 적힌 것만 남는다.

## 구조

```
docs/
├── README.md          ← 이 파일
├── context/           ← 누적 맥락 (지금 어떤 상태인가)
│   ├── 사용자.md        누구인지, 어떻게 대해야 하는지
│   ├── 인프라.md        어떤 도구·저장소를 쓰는지, 무엇을 어디에 두는지
│   └── 작업방식.md      어떤 순서로 일하는지
└── decisions/         ← 결정 로그 (무엇을 왜 정했는가, 날짜순)
    └── YYYY-MM-DD_제목.md
```

**context/** 는 현재 상태를 담는다. 바뀌면 **덮어쓴다.**
**decisions/** 는 역사를 담는다. 한 번 쓰면 **고치지 않는다** (번복하면 새 파일로).

## 새 세션이 시작되면

1. 루트 **`AGENTS.md`** 의 규칙을 따른다 (`CLAUDE.md`는 이 파일을 가리키는 심볼릭 링크)
2. `docs/context/` 를 읽어 현재 상태를 파악한다
3. 필요하면 `docs/decisions/` 에서 왜 그렇게 됐는지 확인한다

> `AGENTS.md` 맨 위에 "세션을 시작하면 `docs/context/`를 읽어라"가 명시돼 있다.
> 그 지시가 자동 로드되는 파일에 있어야 이 폴더가 실제로 읽힌다.
> 근거: `decisions/2026-08-18_AGENTS-md_전환.md`

## 기록하는 시점

아래에 해당하면 **묻지 말고 기록한다.**

- 규칙·방침을 정했을 때 → `decisions/`
- 도구·저장소 구성이 바뀌었을 때 → `context/인프라.md` 갱신
- 사용자에 대해 새로 알게 된 것 → `context/사용자.md` 갱신
- 목표·계획이 생기거나 바뀌었을 때 → `decisions/` + 해당 프로젝트 `handoff.md`

## 기록하지 않는 것

- 진행 중인 작업의 세부 과정 (프로젝트별 `handoff.md`가 담당)
- 코드나 파일 구조 (저장소 자체가 이미 담고 있다)
- 일회성 잡담
